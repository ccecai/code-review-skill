# Code Review Skill：代码审查技能

[English](README.md) | [简体中文](README.zh-CN.md)

这是一套可以重复使用的代码审查规则，供 Codex、Cursor 和支持 Skills 的 ChatGPT 账号使用。
技能指令用英文写，审查结果默认用大白话中文说明。重点检查代码是否适合合入目标分支，
以及模块分工、异常恢复、并发和硬件资源开销是否有问题。

## 快速使用

按下方说明安装后，直接输入：

```text
代码审查
```

或者：

```text
code review
```

用户确实提出审查请求时，助手会根据描述自动选择该技能。只是引用这些词，
或者讨论、修改审查提示词，不会因此启动审查。
自动调用的前提是客户端已经发现这个技能，并判断当前请求与它有关。
需要明确调用时，Codex 可以输入 `$code-review`，Cursor 可以在聊天命令菜单里选择 `/code-review`。

## 检查哪些问题

1. 功能是否正确，BUG 是否从根本上解决，其他调用位置是否仍有同样问题。
2. 代码是否放在该负责的模块和层级，有没有把不相关的业务绑在一起。
3. 改动是否必要，是否复用了已有函数，有没有无关重构、重复实现或多余依赖。
4. 命名、注释和流程是否容易看懂，别人接手后是否容易维护。
5. 是否影响已有功能，以及目标分支、通信协议、接口和保存数据的兼容性。
6. 上电、运行、故障、恢复和关机的状态是否完整，重复事件和旧回调是否处理正确。
7. 失败、超时和资源不足时是否正确退出，释放资源、限制重试并恢复必要状态。
8. 输入、数组边界、数值转换、单位和时间计算是否正确，相关安全保护是否保留。
9. 任务、中断、定时器和回调之间是否打架，有没有死锁、重复释放或外设争用。
10. RAM、Flash、堆、任务栈、CPU、响应时间、功耗和硬件寿命是否受影响。
11. 是否有复现、回归、构建和实机验证证据，哪些内容仍未验证。

硬件相关项目只在有实际关系时检查。减少资源消耗不能牺牲功能、安全、响应时间和可靠性。
测量结果与估算必须分开，不能凭空给出资源占用或性能数字。

## 安装方法

下面的命令适用于 macOS 终端或 Linux 等 POSIX shell，需要先安装 Git。
如果仓库为私有仓库，需要通过有访问权限的 GitHub 账号认证，不要把访问令牌写进链接或命令历史。
如果目标目录已经存在，先查看并备份，再决定如何替换；下面的克隆命令不会覆盖已有安装。

### Codex：当前用户全局安装

使用默认 Codex 目录时执行：

```sh
mkdir -p "$HOME/.codex/skills"
git clone https://github.com/ccecai/code-review-skill.git "$HOME/.codex/skills/code-review"
```

如果设置了自己的 `CODEX_HOME`，改为放在它下面的 `skills/code-review` 目录。
客户端还没发现技能时，开启新会话或重启客户端后再使用。

### Cursor：当前用户全局安装

```sh
mkdir -p "$HOME/.cursor/skills"
git clone https://github.com/ccecai/code-review-skill.git "$HOME/.cursor/skills/code-review"
```

需要时重新打开 Cursor。这种安装面向本机当前用户；远程或云端环境需要单独安装，
或者使用产品提供的技能同步功能。详见 [Cursor 官方说明](https://cursor.com/docs/skills)。

只想在某个项目使用时，把技能放到该项目的 `.cursor/skills/code-review/`
或 `.agents/skills/code-review/` 目录。包含 `SKILL.md` 的文件夹应命名为 `code-review`。

### ChatGPT：导入支持 Skills 的账号

1. 下载 [code-review.zip](code-review.zip)。打开 GitHub 文件页面后，使用下载按钮保存真正的 ZIP 文件。
2. 在 ChatGPT 打开“插件 → 技能 → 创建 → 从电脑上传”。
3. 上传 ZIP，按页面完成扫描和安装。
4. 开启聊天并提出审查请求，同时提供代码、diff、文件，或者通过当前聊天可用的工具提供仓库访问。

ChatGPT 能否使用 Skills 取决于账号资格和工作区设置。
放进本地 Codex 或 Cursor 目录，不会自动安装到 ChatGPT。
如果页面提示账号不能使用技能，这个安装包无法绕过该限制。
详见 [ChatGPT 官方说明](https://help.openai.com/en/articles/20001066-skills-in-chatgpt)。

## 使用示例

检查所有尚未提交的改动：

```text
代码审查：检查当前暂存、未暂存以及相关的未跟踪文件。
```

检查准备合入某个 sprint 的分支：

```text
code review：检查当前分支相对 origin/sprint-2026-11 的改动。
重点看并发、兼容性、RAM/Flash 增长和 CPU 占用，结果用中文。
```

把示例里的分支换成真正的目标分支。助手需要确认比较基准，说明目标分支信息是否可能过期，
不能自行猜测“最新 sprint”是哪一条分支。

在 Codex 明确调用：

```text
$code-review 审查当前更改，用大白话中文说明发现的问题。
```

## 审查方式与输出

没有指定范围时，检查暂存、未暂存和相关未跟踪文件。
指定了分支、PR、提交或文件时，以用户指定范围为准。
除了 diff，还要看相关调用、共享数据、配置和测试，理解改动实际影响的流程。

先列问题，按严重程度排序：

- **P0：** 严重安全问题或大范围故障，需要立即处理。
- **P1：** 合入前必须修复的问题。
- **P2：** 应当修复的普通缺陷。
- **P3：** 影响较小的缺陷。

每个问题说明准确位置、触发条件、具体后果、判断依据和最小修复建议。
已经确认的问题、需要继续验证的风险、可选优化建议分开写。
最后说明审查范围、必要的基准提交、做过和没做过的验证，以及是否有问题阻止合入。

下面只是格式示例，不代表仓库中实际存在这个问题：

```text
[P1] 超时后未释放锁，后续通信会一直等待
位置：src/example.c:42（示例位置）
触发：通信等待超时，函数提前返回。
后果：下一次调用无法拿到锁，通信无法继续。
依据：提前返回分支跳过了公共释放步骤。
建议：让失败分支也经过现有的资源释放逻辑。

验证：仅静态检查；未运行构建或实机测试。
合入：修复此问题后再合入。
```

## 使用边界

- 默认只审查；用户明确要求修复时，才修改代码。
- 审查本身不会执行提交、stash、重置、变基或切换分支。
- 继续遵守项目中的 `AGENTS.md` 和项目规则。
- 技能提供的是工作指令，不会额外提供仓库权限、终端工具或授权。
- 没有构建、测试、实机或目标分支证据时，必须说明。
- “未发现明确问题”不等于已经证明代码没有问题。

## 文件结构与更新

```text
code-review-skill/
├── SKILL.md              # 英文审查指令和自动触发描述
├── agents/
│   └── openai.yaml       # OpenAI 界面信息及自动调用配置
├── README.md             # 英文介绍和使用方法
├── README.zh-CN.md       # 中文介绍和使用方法
└── code-review.zip       # 仅包含技能文件的导入包
```

通过 `git clone` 安装且没有本地改动时，在安装目录执行 `git pull --ff-only` 更新。
如果有本地改动或更新失败，先查看原因，不要直接重置或覆盖。
修改 `SKILL.md` 或 `agents/openai.yaml` 后，需要重新打包 `code-review.zip`，
这两个文件应放在 ZIP 顶层的 `code-review/` 文件夹内。
ChatGPT 中的技能通过产品支持的导入流程更新。
